# 医院陪护床位与消毒交接系统

管理病区、陪护床、申请人、使用时段、押金、床品、消毒批次、维修与归还核验的本地演示系统。
患者与家属资料全部为**匿名演示数据**。

零第三方依赖：仅使用 Node.js ≥ 22.5 内置能力（`node:sqlite`、内置 HTTP、`node:test`、Worker 线程）。

---

## 一条命令启动

```bash
npm start
```

打开 http://localhost:3000 。首次启动若数据库为空，会**自动生成全套演示样例**（申请、占用、归还、床品缺失、污染隔离、消毒失败、维修、临时换床、超时、病区调拨、押金差异）。

其它命令：

```bash
npm run seed     # 重置并重新生成演示数据（data/ 被清空重建）
npm test         # 运行全部 23 个测试
PORT=8080 npm start
```

数据存储：

- SQLite 数据库：`data/care.db`（可用 `CARE_DB_PATH` 覆盖）
- 交接照片：本地目录 `data/photos/`（可用 `CARE_PHOTO_DIR` 覆盖），数据库只存相对路径
- 押金：**进程内模拟适配器**（`InMemoryDepositAdapter`），不连接真实支付

## 业务规则

### 床位分配与并发
- 申请确认后锁定规划时段。
- 可预约床位必须同时满足：**清洁**（消毒批次已完成）、未污染隔离、无未关闭维修单、当前未占用、不在调拨交接中、规格匹配。
- **两名护士同时分配同一床位只允许一人成功**：写操作使用 `BEGIN IMMEDIATE` 串行化，并有数据库级硬约束
  `CREATE UNIQUE INDEX … ON rentals(bed_id) WHERE status='active'` 兜底。
- 维修中的床位不得被预约（自动选床与指定床位都会拦截）。

### 归还核验
- 固定拆成三列：**床架（含床垫）/ 床品 / 配件**；配件按床位台账的应有数量核对实际数量。
- 异常项（缺失 / 损坏 / 污染）**必须填写处理原因**，否则整笔核验被拒并回滚。
- 床架损坏 / 缺失 → 自动开维修单并阻断再次预约。
- 归还后床位立即变脏并自动开消毒批次；污染归还启用含氯擦拭并置隔离。
- 清洁批次「完成」后床位才重新清洁可用；「失败」记录原因、床位保持不可用并自动补开批次。

### 押金（进程内模拟）
- 分配时收取押金（默认 ¥300），每笔流水带唯一**幂等键**，重复提交不重复入账，返回 `duplicated`。
- 结算时汇总：床品/配件缺失、损坏、污染处置费、床架/床垫赔偿、超时使用费（30 分钟宽限，¥2/小时）。
- 赔偿超出押金 → 生成**差异补缴**；不足扣除 → 扣除后退还余额；无异常 → 全额退还。
- 模拟网关失败时整笔事务回滚，无半截流水，可用同一幂等键重试。
- **结算后订单关闭，迟到归还不能重开订单**（需另走线下登记）。

### 其它记录
- **临时换床**：限本病区同规格空闲清洁床；原床解除占用并进入清洁批次。
- **污染隔离**：污染归还/批次即隔离，完成消毒才解除。
- **使用超时**：超过宽限期计费并写入事件流。
- **病区调拨**：必须记录交接数量与双方责任人，经「提议 → 交出 → 接收」两阶段；交接中床位冻结；
  接收后床位转入新病区、重新编号并须重新消毒。

### 病区权限
- 护士通过 `staff_wards` 关联授权病区，只能操作本病区（确认/分配/归还/消毒/维修/调拨）。
- 总务护士（`is_admin`）可跨病区。顶部可切换当前操作员以演示权限拦截。

## 页面

| 路径 | 内容 |
| --- | --- |
| `/` | **病区床位图**：按病区分组；床位卡同时显示清洁、占用、维修、隔离、调拨状态 |
| `/requests` | **申请队列**：确认锁定时段、驳回、自动/指定分配、新建申请 |
| `/rentals` | **使用时间线**：使用时段列表 + 全局交接事件流；单据详情含换床记录与逐事件时间线 |
| `/returns` | **归还核验**：床架/床品/配件三固定列，异常项带处理原因 |
| `/cleaning` | **消毒批次**：排队/进行/失败/完成，开始、完成、登记失败 |
| `/deposits` | **押金结算**：待结算、押金流水、收取/扣除/补缴/退还汇总 |
| `/transfers` | **病区调拨**：发起（多选床位=交接数量）、交出、接收、驳回 |

床位详情 `/beds/:id` 展示固定配件台账（归还核对基准）、维修与消毒历史、照片。

界面配色：临床白 `#f4f8fb`、墨蓝 `#16324f`、湖绿 `#2a9d8f`。

## 测试

```bash
npm test
```

23 个用例覆盖任务要求的五类核心场景：

- **床位竞争**：连续与真实多线程（Worker）并发分配同床，恰好一人成功，且仅一笔押金；自动选床并发同样安全。
- **清洁阻断**：待消毒/批次未完成/失败/隔离/维修各状态阻断预约，完成后恢复；床架损坏自动转维修。
- **配件数量**：呼叫器、脚轮等按台账应有/实际数量计赔；异常缺原因、负数数量被拒。
- **押金幂等**：同键重复只入账一次；网关失败回滚可重试；结算仅一次、不可重开；差异补缴金额正确。
- **病区权限**：跨病区操作被拒；调拨仅交出/接收责任人各自可操作；占用/维修床不可调拨。

另有临时换床、超时计费与完整生命周期端到端用例。

## 代码结构

```
src/
  db.js        SQLite schema（含 active 时段每床唯一部分索引）与连接工厂
  services.js  全部领域规则：分配/归还/消毒/维修/调拨/押金/权限，事务与幂等
  photos.js    交接照片本地存储 + 演示占位 SVG
  seed.js      全套匿名演示样例
  view.js      服务端渲染（无构建、无前端框架）
  server.js    HTTP 路由、会话（当前操作员）、表单与 multipart 上传
test/          node:test 测试与夹具、并发 worker
```
